================================================================================
모집중 (mojibjung) 플랫폼 전체 기능 명세서 & 테스트 가이드 (대/소기능 통합본)
================================================================================

이 파일은 모집중 플랫폼의 대형 핵심 기능부터 구석구석의 소형 유틸리티 기능까지 모든 기능(전체 9개 영역, 50+ 항목)을 테스트 시나리오와 함께 상세히 정리한 공식 안내서입니다.

--------------------------------------------------------------------------------
1. 가입 및 인증 시스템 (Sign Up & Authentication)
--------------------------------------------------------------------------------
[1-1] 카카오 소셜 로그인 (Kakao OAuth 2.0)
  * 설명: Kakao 계정 로그인을 통해 회원가입/로그인 처리를 실행하고 HttpOnly 세션 쿠키를 발급받습니다.
  * 테스트: 홈 화면 우측 상단 '로그인' 버튼 클릭 -> 카카오 로그인 동의 진행 -> 로그인 성공 후 프로필 아바타로 변경되는지 확인.

[1-2] 미인증 가입 대기 계정 격리 가드 (Onboarding Guard)
  * 설명: 소셜 로그인 직후 학적 인증을 완료하지 않은 유저(pending 상태)는 일반 페이지 접근이 완전 차단되며 온보딩 절차로 강제 이동합니다.
  * 테스트: 가입 완료 전 브라우저 주소창에 직접 `/board` 나 `/mypage` 경로를 입력하고 강제 이동 시, 온보딩 주소(`/onboarding/email`)로 즉각 리다이렉트되는지 검증.

[1-3] 학교 이메일 도메인 검증
  * 설명: 오직 `@hufs.ac.kr` 혹은 `@hufs.co.kr` 등의 정식 학교 이메일 주소 포맷만 입력을 허용합니다.
  * 테스트: 온보딩 1단계 화면에서 `test@naver.com` 입력 후 발송 클릭 -> 도메인 경고 오류 출력 확인 -> `student@hufs.ac.kr` 입력 시 정상 진행 확인.

[1-4] 6자리 OTP 인증 코드 발송 및 Failover (이중화)
  * 설명: 이메일 전송 실패 방지를 위해 SMTP 발송 실패 시, 클라우드 메일 서비스인 Resend API로 자동 Failover(우회 발송) 처리합니다.
  * 테스트: 인증 코드 전송 클릭 시 메일함에 6자리 숫자 코드가 도착하는지 확인.

[1-5] 일회용 OTP 검증 및 타이밍 공격 방어 (Timing Safe Equal)
  * 설명: DB에는 6자리 코드의 SHA-256 해시값만 저장하며, 검증 비교 시 타이밍 공격을 막는 상수 시간 비교(timingSafeEqual)를 가동합니다. 인증 코드는 5분 유효하며, 1회 사용 시 즉시 만료됩니다.
  * 테스트: 메일로 온 인증 코드를 다르게 입력(오류 카운트 누적 확인) -> 올바른 코드 입력하여 통과 -> 동일 코드로 재입력 시 만료/사용 불가 에러 검증.

[1-6] 실명 기반 학적 입력 및 1인 1계정 제약 (Partial Unique)
  * 설명: 온보딩 3단계에서 실명, 학번, 학과(마스터 DB), 입학년도를 입력합니다. 학번 및 인증 메일은 DB 부분 유니크 제약조건에 의해 다수의 NULL 가입 유저는 충돌을 방지하되 정회원 간 중복 가입은 원천 차단합니다.
  * 테스트: 이미 가입된 다른 회원의 학번이나 메일 주소로 온보딩 완료 시도 -> 중복 가입 오류 문구 확인.

[1-7] 회원 탈퇴 및 원자적 연쇄 삭제 (Atomic Cascade Delete)
  * 설명: 회원 탈퇴 시, DB의 물리적 락 경합 방지를 위해 물리 외래키를 배제하고 어플리케이션 트랜잭션 단위로 프로필, 댓글, 지원서, 쪽지, 일정, 채팅, 그룹 정보 등 유저 소유의 모든 테이블 행 데이터를 수동으로 일제 연쇄 삭제합니다.
  * 테스트: 마이페이지 하단 '회원 탈퇴' 실행 -> DB에서 해당 유저의 모든 데이터(applications, messages 등)가 완전히 제거되었는지 및 즉시 세션 쿠키가 만료되는지 확인.

2. 모집글 관리 및 검색 시스템 (Recruitment Posts & Search)
--------------------------------------------------------------------------------
[2-1] 모집글 작성/수정/삭제 (CRUD)
  * 설명: 동아리/학회/스터디 카테고리를 설정하여 모집글을 올릴 수 있으며, 최대 5개의 키워드 태그와 모집 인원 및 마감일을 입력합니다.
  * 테스트: [모집글 작성] -> 제목, 내용 작성 및 태그 기입 -> 작성 완료 및 상세 화면 이동 확인 -> 작성자 본인 계정으로 수정/삭제 정상 동작 검증.

[2-2] 노션 스타일 동적 질문 폼 빌더 (Custom Form Builder)
  * 설명: 지원자에게 받을 문항 스펙을 JSONB로 직렬화하여 저장합니다. 주관식 단답형/서술형, 객관식 단일 선택(라디오)/다중 선택(체크박스) 질문을 임의로 디자인할 수 있습니다.
  * 테스트: 모집글 작성 중 '+ 질문 추가' 클릭 -> 주관식 및 객관식 문항 추가 -> 저장 후 지원자 시점에서 해당 질문 항목들이 Zod 검증 스키마와 함께 올바른 UI창으로 동적 렌더링되는지 확인.

[2-3] 면접 전형 설정 및 1:1 비밀 배정
  * 설명: 모집글에 면접 절차가 있는 경우 스위치를 켜며, 서류 합격자 처리 시 면접 시간/장소를 기입하면 지원자 본인에게만 1:1 비밀 정보로 캘린더 및 마이페이지에 노출됩니다.
  * 테스트: 모집글 작성 시 '면접 전형 있음' 토글 ON -> 지원자 서류 수락 시 면접 상세 내용 입력란 활성화 -> 작성 후 지원자 계정의 캘린더/마이페이지에 면접 상세 내용이 비밀글 형태로 잘 나타나는지 확인.

[2-4] 다중 조건 필터 및 실시간 텍스트 검색
  * 설명: 카테고리별 분기, 모집 중/마감 필터, 정렬(최신순, 인기순, 추천순)을 지원하며 검색란 입력 시 키워드 자동완성이 팝업 형태로 구동됩니다.
  * 테스트: 검색창에 한 글자 입력 시 관련된 매칭 태그들이 드롭다운에 자동 완성되는지 검증 -> 특정 필터를 적용했을 때 게시글 그리드가 올바르게 리프레시되는지 확인.

[2-5] 좋아요 및 북마크 토글
  * 설명: 모집글 우측 하단 하트(좋아요) 및 북마크 버튼을 누르면 실시간 반영됩니다. 북마크 시 해당 모집글의 마감 일정 정보가 내 마이 캘린더에 자동으로 동기화됩니다.
  * 테스트: 북마크 클릭 -> 마이 캘린더 페이지로 이동 -> 달력 내 해당 모집글 마감 일자가 깃발(D-Day) 아이콘과 함께 표시되는지 검증.

[2-6] 관심 키워드 기반 개인화 추천
  * 설명: 내 프로필 관심 키워드(최대 10개)와 모집글 태그 간 교집합 원소 개수가 가장 많은 글을 상위에 노출하는 매칭 피드 정렬 기술입니다.
  * 테스트: 프로필 설정에서 관심 키워드를 `개발`, `React` 로 설정 -> 홈 화면의 추천 목록 상단에 해당 태그가 포함된 모집글들이 정렬되어 나타나는지 확인.

3. 지원 및 전형 관리 시스템 (Application Management)
--------------------------------------------------------------------------------
[3-1] 다이내믹 지원서 제출 및 중복 지원 제약
  * 설명: 작성자가 지정한 커스텀 문항에 답변을 채워 접수합니다. 복합 UNIQUE 제약조건에 의해 동일 모집글에는 1회만 지원할 수 있습니다.
  * 테스트: 모집 상세글 하단 '지원하기' 클릭 -> 동적 폼 답변 채우고 제출 -> 완료 후 상세글 하단 버튼이 '지원 완료' 상태로 변하며 재지원 시도가 차단되는지 확인.

[3-2] 지원자 통계 대시보드 시각화 (Recharts)
  * 설명: 모집글 작성자는 지원자들의 성별, 학년, 학과 분포율 및 문항별 객관식 응답 통계를 시각적인 그래프(Pie, Bar 차트)로 모니터링할 수 있습니다.
  * 테스트: 모집글 작성자 계정으로 **[지원자 관리]** 진입 -> 상단의 Recharts 차트 통계 도표(성별 비율 원형 그래프, 지원 문항 분포 그래프 등)가 정상 집계되어 그려지는지 확인.

[3-3] 4단계 전형 제어 및 거절 사유 전송
  * 설명: 지원서의 합격 상태를 `대기중` -> `1차합격` (면접 배정 가능) -> `수락` (최종 합격 및 그룹 자동 가입) / `거절` 단계로 관리합니다. 거절 처리 시 구체적인 사유를 기입해 발송할 수 있습니다.
  * 테스트: [지원자 관리] 보드에서 카드 드래그 또는 버튼 클릭으로 '거절' 상태 변경 -> 팝업에 거절 사유 입력 후 확인 -> 지원자 계정으로 접속 시 알림 센터 및 마이페이지에 합격 상태 변경 사항과 거절 사유 텍스트가 노출되는지 검증.

--------------------------------------------------------------------------------
4. 자치 그룹 관리 시스템 (Group Hub System)
--------------------------------------------------------------------------------
[4-1] 그룹 자동 생성 및 합격 단원 자동 가입 연동 (Auto-Join)
  * 설명: 모집글 작성 시 연동할 그룹을 설정해 놓으면, 지원자를 최종 '수락' 처리함과 동시에 해당 유저가 그룹 단원으로 자동 등록됩니다.
  * 테스트: 지원자를 최종 수락 -> 수락된 유저 계정으로 로그인 후 **[그룹/소모임]** 목록에 해당 그룹이 자동으로 들어가 있는지 확인.

[4-2] accessKey 코드를 이용한 그룹 즉시 가입
  * 설명: 비공개 단체 가입용 고유 키(`XXXX-XXXX-XXXX` 포맷)를 입력하여 관리자의 개별 승인 절차 없이 즉시 멤버로 합류합니다.
  * 테스트: 그룹 허브 설정에서 accessKey 복사 -> 다른 회원 계정으로 로그인 후 [그룹 입장 코드 입력] 창에 키 입력 -> 해당 그룹 멤버로 즉시 편입되는지 검증.

[4-3] 커스텀 직책 지위 및 세부 권한 스위치 (groupRoles)
  * 설명: 그룹 내 "회장", "기획팀장" 등 커스텀 지위를 생성하고, 지위별 권한(일정 관리, 공지 관리, 비밀일정 열람)을 설정할 수 있습니다.
  * 테스트: 그룹 리더 계정으로 **[그룹 설정] → [지위 설정]**에서 새 지위 개설 -> 특정 권한 체크 및 저장 -> 멤버 목록에서 임의의 부원에게 해당 직책을 할당 -> 해당 부원 계정으로 접속 시 권한 스위치에 맞춰 UI 및 API가 동작하는지 확인.

[4-4] 멤버 강퇴 및 자진 탈퇴
  * 설명: 운영진 권한으로 특정 부원을 방출할 수 있으며, 일반 부원은 그룹 허브를 통해 자진해서 탈퇴할 수 있습니다.
  * 테스트: 그룹 리더로 멤버 목록 진입 -> 강퇴 버튼 클릭 시 멤버 매핑 행이 삭제되는지 확인 -> 부원 계정으로 '그룹 탈퇴' 클릭 시 정상 해제되는지 확인.

[4-5] 아코디언 그룹 공지사항
  * 설명: 그룹 공지사항 등록 권한이 있는 부원이 공지를 게시할 수 있으며, 아코디언 UI를 통해 깔끔하게 펼쳐 읽을 수 있습니다.
  * 테스트: 공지 작성 권한 계정으로 공지 등록 -> 공지 탭 피드에 목록 카드 렌더링 확인 -> 클릭 시 아코디언처럼 아래로 텍스트 본문이 슬라이드 오픈되는지 확인.

[4-6] 실시간 그룹 대화방 (채팅)
  * 설명: 그룹 부원들이 공유하는 실시간 채팅 채널로, 발송자의 실명 정보와 전송 시간이 함께 타임라인 형태로 표시됩니다.
  * 테스트: 채팅 메시지 입력 후 전송 -> 말풍선 렌더링 및 스크롤 자동 하단 이동 확인 -> 다른 부원이 로그인했을 때 대화 기록이 정상 로딩되는지 검증.

[4-7] 그룹 자료실 로컬 파일 업로드 및 다운로드 (Cloudinary 연동)
  * 설명: 컴퓨터 로컬 저장소나 파일 탐색기에서 최대 10MB 크기의 실제 파일을 선택해 업로드하고, 공유 목록에서 편리하게 다운로드 및 삭제할 수 있습니다.
  * 테스트: **[자료실]** 탭 진입 -> 파일 선택기(Input)를 열어 기기 내 실제 PDF/이미지 파일 선택 -> 업로드 실행 -> 목록에 파일 크기와 타입이 올바르게 적재되고 클릭 시 다운로드되는지 검증.

[4-8] 하위 스터디 개설 및 스터디장 위임
  * 설명: 동아리/학회 내부에 개별 소모임 또는 스터디를 개설하고 특정 부원을 스터디장(Study Leader)으로 임명합니다.
  * 테스트: 그룹 리더 계정으로 **[소모임/스터디]** 탭 진입 -> **"+ 신규 스터디 개설"** 클릭 -> 이름, 설명 입력 및 스터디장 임명 지정 후 저장 확인.

[4-9] 스터디장용 스터디원 구성 저장 (체크박스 매핑)
  * 설명: 임명된 스터디장은 상위 그룹 멤버 중 스터디에 합류할 단원들을 체크박스로 매핑하여 한 번에 저장할 수 있습니다.
  * 테스트: 임명된 스터디장 계정으로 해당 스터디 워크스페이스의 **[팀원 구성]** 탭 진입 -> 멤버 리스트 체크 후 **"팀원 구성 저장"** 클릭 -> 멤버 저장이 완료되었는지 확인.

[4-10] 주차별 회의록 작성/수정/삭제 및 비소속 단원 격리 가드
  * 설명: 스터디원들은 회의록 및 요약 문서를 CRUD 할 수 있으며, 스터디에 소속되지 않은 일반 그룹원은 워크스페이스 및 회의록 열람 접근이 불가하도록 tRPC 단에서 완전 격리합니다.
  * 테스트: 스터디원 계정으로 회의록 등록 및 상세 모달 조회 -> 스터디원이 아닌 일반 그룹원으로 로그인 후 해당 스터디 진입 시 차단되거나 비공개 안내가 출력되는지 검증.

[4-11] 활동 종료 아카이빙 및 메인 홈 전시관 발행
  * 설명: 스터디/동아리 활동 완료 시 리더가 최종 회고록(수수 프로젝트 링크, 참여 멤버, 대표 이미지 등)을 입력하여 아카이브 포트폴리오를 발행합니다. 발행 후 그룹 허브는 읽기 전용(글쓰기/채팅 잠금)이 되며 메인 홈 하단에 전시됩니다.
  * 테스트: 그룹 리더 계정으로 아카이브 발행 진행 -> 그룹 내 모든 채팅창 입력, 글쓰기 등 쓰기 동작이 차단되는지 확인 -> 홈 화면으로 이동하여 전시관 그리드 및 모달 팝업으로 발행 포트폴리오가 완벽히 렌더링되는지 확인.

--------------------------------------------------------------------------------
5. 마이 캘린더 시스템 (Unified Calendar)
--------------------------------------------------------------------------------
[5-1] 일정 통합 병합 피드 (Unified Feed)
  * 설명: 개인 스케줄, 학교 공식 학사일정 및 공휴일(보라색), 내 그룹 일정, 북마크한 모집 마감일(D-Day 깃발)을 단일 달력 그리드에 병합 노출합니다.
  * 테스트: 캘린더 페이지 진입 -> 각각 다른 카테고리의 일정들이 색상 및 레이블 분류 범례에 맞춰 정상적으로 표시되는지 확인.

[5-2] 겹침 방지 수평 레인 정렬 알고리즘 (Greedy Lane Partitioning)
  * 설명: 한 날짜에 일정이 여러 개 겹칠 때 화면 붕괴를 방지하기 위해 일정 가로 길이가 긴 순으로 정렬하여 최대 3개의 레인에 분배하며, 초과분은 카운트로 접어둡니다.
  * 테스트: 한 주에 4개 이상의 연속된 긴 일정을 등록 -> 달력 그리드 상에 일정이 3단까지만 깔끔하게 배치되고 그 아래에 "+N개 더보기" 카운트가 표시되는지 확인.

[5-3] 일정 카테고리 컬러 개인별 커스텀 지정
  * 설명: 개인 일정을 등록하거나 수정할 때, 달력에서 시각화될 테마 컬러를 개인 취향에 맞게 파스텔 서클 파티션으로 선택 및 반영합니다.
  * 테스트: 일정 생성창에서 카테고리 테마 색상 서클 클릭 후 저장 -> 달력 그리드 내 수평 바 배경색이 지정한 색상으로 즉시 변하는지 확인.

[5-4] 일정 참석 여부 RSVP 투표 및 운영진 명단 집계
  * 설명: 그룹 일정인 경우 참석/불참/보류 투표창이 활성화되며, 리더 및 관리자는 누가 어떤 항목에 투표했는지 실시간 개별 명단을 열람할 수 있습니다.
  * 테스트: 달력 내 그룹 일정 클릭 -> RSVP 참석/불참/보류 버튼 투표 진행 -> 리더 계정으로 '상세 명단 보기' 클릭 시 투표자 실명 및 상태 정보가 실시간 출력되는지 확인.

[5-5] 데일리 투두 리스트 연동 및 진행률 위젯
  * 설명: 일정 클릭 시 우측 스케줄 상세창 하단에 체크리스트(투두)를 기입할 수 있으며, 달력의 일정 바에 완료 진행률이 프로그래스바로 표기됩니다.
  * 테스트: 일정에 3개의 투두 항목 입력 -> 1개 체크 완료 -> 달력 내 해당 수평 일정 바 내부에 33% 영역만큼의 프로그래스바 색상이 채워지는지 확인.

[5-6] 독립형 마이 투두 전용 서브 페이지
  * 설명: 투두리스트만 전담하여 빠르고 직관적으로 관리할 수 있는 마이 투두 단독 페이지를 별도로 마련했습니다.
  * 테스트: 네비게이션 메뉴 또는 캘린더 페이지에서 '투두 모아보기' 클릭 -> 투두 단독 화면(`TodoPage`)으로 깔끔하게 전환 및 생성/완료 토글 검증.

--------------------------------------------------------------------------------
6. 소통 및 쪽지 시스템 (Direct Messaging)
--------------------------------------------------------------------------------
[6-1] 1:1 쪽지 스레드 및 실시간 대화
  * 설명: 모집글 관련 질의나 개인 소통을 위해 1:1 쪽지방을 신설하여 메시지를 주고받습니다.
  * 테스트: 다른 회원 프로필 진입 -> '쪽지 보내기' 클릭 -> 메시지 전송 -> 상대방이 로그인했을 때 대화방 스레드에 실시간 메시지가 나타나는지 확인.

[6-2] 쪽지방 진입 시 실시간 읽음 동기화 및 알림 연동
  * 설명: 쪽지방에 입장하는 순간 상대방이 보낸 미독 메시지들이 일괄 읽음(`isRead = true`) 처리되어 상단 네비게이션 배지 카운트에서 실시간으로 감산됩니다.
  * 테스트: 알림 배지에 미독 쪽지 수 표시 감지 -> 해당 쪽지방 클릭 진입 -> 배지 숫자가 즉각 줄어들고 미독 마크가 사라지는지 검증.

[6-3] 상호 차단(Block) 및 대화/추천 차단 가드
  * 설명: 특정 사용자를 차단하면 양방향 쪽지 전송이 거부되며, 메인 홈 추천 피드나 검색 자동완성 유저 목록 등에서 대상자의 모든 정보가 스크리닝됩니다.
  * 테스트: A 유저가 B 유저를 차단 -> B 유저 대화방에서 A 유저에게 쪽지 전송 시도 -> 차단된 회원 안내 오류 발생 및 전송 거부 확인 -> A 유저 홈 화면에서 B 유저의 모집글 차단 여부 검증.

--------------------------------------------------------------------------------
7. 실시간 알림 센터 (Real-time Notification)
--------------------------------------------------------------------------------
[7-1] 🔔 상단 알림 팝오버 배지 및 펄스 효과
  * 설명: 미확인 실시간 알림 수신 시 네비게이션 바 종 모양 아이콘에 개수 배지가 활성화되며, 맥박이 뛰는 듯한 펄스 애니메이션이 가동됩니다.
  * 테스트: 다른 계정으로 내 모집글에 댓글 작성 시도 -> 즉각 내 화면 상단 종 아이콘 옆에 붉은색 맥박 효과 배지 카운트가 나타나는지 확인.

[7-2] 알림 클릭 읽음 및 다이렉트 바로가기 (Deep Link)
  * 설명: 알림을 클릭하면 해당 알림이 즉각 읽음 처리되며, 댓글이 작성된 게시글이나 수신된 쪽지방 등 목적지 경로로 즉시 랜딩시킵니다.
  * 테스트: 종 아이콘 클릭 -> 드롭다운 리스트 열림 -> 특정 댓글 알림 클릭 -> 해당 게시글 상세창 댓글 영역으로 자동 스크롤 이동 및 알림 읽음 마크 전환 검증.

--------------------------------------------------------------------------------
8. 우수 스터디 & 동아리 아카이브 전시관 (Showcase)
--------------------------------------------------------------------------------
[8-1] 메인 홈 하단 전시관 및 반응형 캐러셀 슬라이더
  * 설명: 활동 아카이빙을 완료하고 아카이브 포트폴리오를 발행한 우수 단체들이 메인 홈 화면 하단 전시관 영역에 노출됩니다.
  * 테스트: 홈 화면 하단으로 스크롤 -> 발행된 아카이브 카드들의 캐러셀 슬라이더 렌더링 확인.

[8-2] 매거진 레이아웃 아카이브 상세 회고록 모달
  * 설명: 아카이브 전시관 카드를 클릭 시, 대표 사진, 참여 멤버 실명 태그, 수행 요약, 회고 본문이 매거진 형태의 미려한 레이아웃 모달 팝업으로 나타납니다.
  * 테스트: 전시 카드 클릭 -> 아카이브 요약/회고 모달 팝업 활성화 확인 -> 내역 검증 후 닫기 클릭.

9. 신고 및 관리자 시스템 (Report & Admin Panel)
--------------------------------------------------------------------------------
[9-1] 부적절 콘텐츠 통합 신고 (Reports)
  * 설명: 악성 모집글, 댓글, 쪽지, 유저를 지정하여 신고 분류(광고, 욕설, 유해물 등)와 사유를 기입해 신고 접수합니다.
  * 테스트: 임의의 댓글 우측 신고 아이콘 클릭 -> 사유 선택 후 제출 -> 신고 완료 안내 확인.

[9-2] 관리자 대시보드 회원 제재 및 사유 안내 격리 (Disabled Page)
  * 설명: 관리자 계정(`role === admin` 혹은 OWNER_OPEN_ID 유저)으로 접수된 신고 내역을 심사해 반려/인정 처리하거나, 특정 회원을 강퇴/정지(Disabled) 시킬 수 있습니다. 정지된 회원은 쿠키 세션이 파기되며 로그인 시 정지 사유 안내 격리 화면으로 격리됩니다.
  * 테스트: 관리자 계정으로 [관리자 페이지] -> 유저 목록에서 특정 계정 '정지' 처리 및 사유 입력 -> 정지된 유저 계정으로 로그인 시도 -> 메인 홈이 아닌 '계정 정지 사유 안내 및 이의 제기' 검은색 격리 화면으로만 랜딩되는지 확인.

[9-3] 백엔드 메일 인프라 SMTP 전송 자격 실시간 검증 (getSmtpStatus)
  * 설명: 서버에 이식된 SMTP 및 Resend 메일 발송 장치의 가동 상태를 실시간 진단하여 관리자 화면에 에러 여부를 출력합니다.
  * 테스트: 관리자 계정으로 [관리자 페이지] -> 상단 '메일 서버 상태 진단' 클릭 -> 'SMTP 가동 가능 / Resend API 활성화' 등의 실시간 네트워크 인프라 자격 통과 메시지 검증.
